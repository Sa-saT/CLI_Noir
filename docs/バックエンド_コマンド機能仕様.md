# バックエンド コマンド機能仕様（MVP）

evaluator 実装時の書き漏れを防ぐためのコマンド定義書。  
allowlist/denylist 定義・エラーメッセージ定義は `設計指示書.md` § 8, § 12 を正とする。

---

## 0. 実装ルール（共通）

- 判定順序: `denylist → allowlist → コマンド実行`（`設計指示書.md` § 8 参照）
- `git` は第1トークンで判定後、サブコマンドを別途分岐する
- エラー文言は `設計指示書.md` § 12 の一覧を使う
- 不正コマンドは即失敗にせず `Error: command not allowed` を返す

---

## 0.5 evaluator の実装方式（2026-07-06 追加）

### アーキテクチャ

```
入力行
 → tokenizer（shlex ベース。引用符・エスケープを正しく処理）
 → parser（パイプ / リダイレクトの分解。MVP は「単一コマンド + > >>」のみ、
           Phase2 で | と 2> を追加する小さな再帰下降パーサ）
 → denylist / allowlist 判定（第1トークン）
 → command registry から実装関数を引いて実行
 → 出力行（style 付き）と新 state を返す
```

### 設計原則

1. **純粋関数**: 各コマンドは `(state, argv, stdin_lines) -> (stdout_lines, new_state)` のシグネチャで実装する。副作用を持たないため、パイプは関数合成（前段の stdout を次段の stdin に渡す fold）で自然に実現でき、テストも入出力の表明だけで書ける
2. **registry パターン**: `@command("grep")` のようなデコレータ登録制にする。コマンド追加 = 関数を1つ書いて登録するだけ、の構造を保つ
3. **実 OS 禁止**: `subprocess` / `os.system` / 実ファイルパスへのアクセスは evaluator 内で一切使わない（import 自体をしない）。glob は `fnmatch`、正規表現は `re` で仮想FS に対して評価する
4. **トークナイズを自作しない**: 引用符処理（`"top secret.txt"` / `git commit -m "探索 メモ"`）は `shlex.split` に任せる。正規表現による手書きパースは引用符・エスケープで必ず破綻する
5. **パス解決の一元化**: 絶対/相対/`..`/remote 切替の解決は `resolve_path(state, path)` ヘルパー 1 箇所に集約する（コマンドごとに書かない）

### テスト方式

- 各コマンド: 正常系/異常系のユニットテスト（純粋関数なので fixture の state を渡すだけ）
- Mission 単位: `docs/AUTHORING_GUIDE.md` § 5 の `tests.happy_path` / `error_cases` 配列を
  そのまま pytest のパラメータとして流す**ゴールデントランスクリプトテスト**にする
  （コマンド列を順に evaluator に通し、最終 state のクリア判定と各段のエラー文言を表明する）

## 2. 基本コマンド

### `ls [path]`
- 前提: `path` 未指定時は `current_path`
- 正常: 対象ディレクトリ配下を一覧表示
- 異常: 対象が存在しない場合 `Error: path not found`
- state更新: なし

### `cd [path]`
- 前提: 移動先がディレクトリとして存在する
- 正常: `current_path` を更新。`path` 省略時は `$HOME` へ移動する（実 bash と同じ挙動。P3-07 / BUG-02, 2026-08-16）
  - local 時: `env_vars["HOME"]`（既定 `/root`）
  - ssh 接続中: 接続先のログインディレクトリ（`SSH_HOSTS[ssh_host]["initial_path"]`。`cmd_ssh` は `env_vars` を退避・差し替えしないため、remote 中も `env_vars["HOME"]` は local のまま使えない）
- `cd -`: 直前の `OLDPWD` へ移動し、実 bash と同じく移動先の絶対パスを1行出力する（UX-01a, 2026-09-12）。成功した `cd` は必ず移動前の `current_path` を `env_vars["OLDPWD"]` に記録する。`OLDPWD` 未設定時は `Error: directory not found`
- `~` 展開: 引用符なしトークンの `~` 単体・`~/...` を `$HOME` 相当パスへ展開する（`cd ~` 等。`~user` 形式のユーザー名付きは非対応で展開しない）
- 異常: `Error: directory not found`
- 制約: remote から local へは `cd` で戻れない（`exit` のみ）

### `pwd`
- 正常: `current_path` を表示
- state更新: なし

### `touch <file>`
- 正常: ファイル生成（未存在時）
- 異常: 親ディレクトリ不正時 `Error: path not found`
- state更新: `filesystem`

### `mkdir <dir>`
- 正常: ディレクトリ生成
- 異常: 既存名の場合 `Error: directory already exists`
- state更新: `filesystem`

### `cat <file>`
- 正常: ファイル内容を返す
- 異常: `Error: file not found`
- state更新: なし

### `less <file>`
- 正常: ページング表示（MVP は全体返却でも可）
- 異常: `Error: file not found`
- state更新: なし

### 共通構文（2026-09-12 追加。UX-01a）
- `>file` / `>>file` / `2>file`: リダイレクト記号と対象パスが空白無しで連結された表記（実 bash で頻出）にも対応する。空白ありの `> file` `>> file` `2> file` と同じ意味
- `&&` / `||` / `;`: 未対応構文（設計指示書 § 8 の構文レベルに含まれない）。使用すると `Error: invalid input`（`$?=1`）を返し、一部だけ黙って実行することはしない（例: `cd desk && pwd` は `cd` だけ実行されたりしない）。引用符の中（`echo "a;"` 等）は文字列なので対象外

### `echo ...`
- 正常: 文字列表示またはリダイレクト先へ追記
- 異常: リダイレクト先の親パス不正時 `Error: path not found`
- state更新: `filesystem`（追記時）

### `history`
- 正常: `command_log` を実 bash 相当の書式（`%5d  cmd`。右寄せ5桁 + 空白2つ）で表示する。実行中の `history` 自身は含めない
- Mission15: `MissionDef.informant_history`（情報屋の履歴演出）があれば最優先でそちらを表示する
- state更新: なし

### `clear`
- 正常: ターミナル表示クリア
- state更新: なし

## 3. 検索/整形コマンド

### `grep <pattern> <file>`
- 正常: 一致行を返す
- 異常: ファイルなし `Error: file not found` / パターン不正 `Error: invalid pattern`

### `egrep <pattern> <file>` / `fgrep <pattern> <file>`
- `grep -E` / `grep -F` の旧別名。**grep と同一の実装を呼ぶ**（registry で alias 登録。個別実装しない）
- 正常: 出力の先頭に非推奨警告を 1 行付けてから一致行を返す（実 GNU grep と同挙動）
  - `egrep: warning: egrep is obsolescent; using grep -E`
  - `fgrep: warning: fgrep is obsolescent; using grep -F`
- fgrep はパターンを正規表現として解釈せず固定文字列一致（`re.escape` 相当）
- 異常: grep と同じ
- state更新: なし

### `find <path> ...`
- 正常: 条件一致ファイルを返す
- 異常: パス不正 `Error: path not found`

### `sort`
- 正常: 入力行を昇順で返す
- 異常: 入力不正時 `Error: invalid input`

### `uniq`
- 正常: 重複行をまとめて返す
- 異常: 入力不正時 `Error: invalid input`

### `awk <expr> <file>`
- 正常: 条件一致結果を返す
- 異常: 式不正 `Error: invalid awk expression` / ファイルなし `Error: file not found`

## 4. SSH / Remote

### `ssh <host>`
- 正常: `remote_mode=true`, `ssh_host=<host>`, `current_path=<remote初期パス>`
- 異常:
  - 未登録ホスト: `Host not found`
  - 権限不可: `Permission denied`

### `exit`
- 正常: local に戻す（`remote_mode=false`, `ssh_host=null`, `current_path=/root`）
- 異常: local で実行時は no-op またはガイド文言

## 5. 疑似Git

`git` はサブコマンドで分岐する:
- `git status`
- `git add`
- `git commit -m "<msg>"`
- `git push`

### `git status`
- 正常: `git_state` に応じて 1 行目に現状、2 行目に次の一手の案内（実 git の `(use "git add ..." ...)` 相当。UX-02, 2026-09-13）
  - `Changes staged`（add 済み・commit 未）→ `git commit -m` を案内
  - `No commits yet`（commit が 1 つも無い）→ `git add .` → `git commit -m` を案内
  - `Ready to push`（commit 済み + case_checked）→ `git push` を案内
  - `Nothing to commit`（commit 済みだが case_checked 未）→ `sh case_file.sh` を案内
  - ※旧実装は commit 済みで `No commits yet` を返す反転バグがあった（2026-09-13 修正）

### `git add`
- 正常: 変更ファイル + mission_flags の現在値を staged に上げる
- state更新: `git_state.staged`

### `git commit -m`
- 前提: staged あり + message 1文字以上
- 正常: 現在の state snapshot（current_path / filesystem / mission_flags）を commits 配列に追加
- 異常:
  - staged なし: `Error: nothing to commit`
  - message なし: `Error: commit message required`
- state更新: `git_state.commits` に新規 commit を push
- 1 Mission 中に何度でも実行可（複数セーブポイント）

### `git push`
- 前提: commits が 1 件以上存在する
- 正常: 最新 commit の snapshot を判定し、`case_checked=true` なら `git_state.pushed=true` + その commit に `pushed=true` の印 → ミッション完了（`progress.advance_mission`）
- 異常:
  - commit なし: `Error: push not allowed before commit`
  - クリア条件未達 / 最新 commit が現在の Mission のものでない: `Error: mission requirements not met`
- commit 履歴はプレイ全体で 1 本（Mission 遷移で消去しない）。印付き commit へ resume するとクリア直後から再開する（設計指示書 § 4 セーブ選択）

### 5b. ブランチ・マージ・PR（追加エピソード git 編 Mission23〜25。2026-09-13 確定、実装中）

疑似 Git の原則（commit=セーブ / push=クリア判定）は据え置き。ブランチは**作業ディレクトリ（リポジトリ）配下だけ**を
管理する（実 git と同じ。世界全体ではない）。リポジトリは Mission23 解放時に `git_state.repo` として作られる:

```json
"repo": {
  "root": "/root/team_desk",
  "current_branch": "main",
  "branches": {
    "main": { "tree": { …/root/team_desk の children スナップショット… }, "base": null,
              "log": [ { "id": "a1b2c3d", "message": "initial case notes" } ] },
    "reed/statement": { "tree": {…}, "base": {…分岐時点の tree…}, "log": [...] }
  },
  "merging": null,
  "prs": [ { "number": 12, "title": "…", "body": "…", "branch": "report/harbor", "state": "open",
             "reviews": [ { "by": "Chief Morgan", "state": "CHANGES_REQUESTED", "comments": ["…"] } ] } ]
}
```

- `tree` は `filesystem` の該当ディレクトリ `children` の deepcopy。`base` は分岐元の tree（三方マージの共通祖先）。
  `log` は枝ごとの短い履歴（`git log` 表示用。id は 7 桁 hex 風の連番）
- リポジトリ外（`/root/desk` 等）は従来どおり枝の影響を受けない。`git commit` は**従来のセーブ（世界全体のスナップショット）
  に加えて**、repo があれば現在の枝の `tree` を更新し `log` に積む

| コマンド | 挙動 | 異常 |
|---|---|---|
| `git branch` | 枝を一覧。現在の枝に `* ` | — |
| `git checkout -b <name>` | 現在の枝の tree を base/tree にコピーして新しい枝を作り切り替える | 既存名: `Error: a branch named '<name>' already exists` |
| `git checkout <name>` | 切り替え。`/root/team_desk` の children を枝の tree に差し替える（cwd が配下なら維持） | 未コミットの変更あり（tree ≠ 現在の中身）: `Error: commit your changes before switching branches` / 無い枝: `Error: pathspec '<name>' did not match any branch` |
| `git log` | 現在の枝の log を新しい順に `<id> <message>` | — |
| `git diff <a> <b>` | 2 枝の tree の差分（ファイル単位 + 行単位 `<`/`>`。cmd_diff の形式を流用）| 無い枝 |
| `git merge <name>` | 三方マージ。ファイルごとに: 相手だけ変更→採用 / 自分だけ変更→維持 / 両方同じ→維持 / 両方別々→**競合**。行数が同じファイルは行単位で競合行だけを `<<<<<<< HEAD` `=======` `>>>>>>> <name>` で囲み、行数が違えばファイル全体を囲む。自分の tree が base のままなら `Fast-forward`、それ以外は `Merge made by the 'ort' strategy.`。競合があれば `CONFLICT (content): Merge conflict in <file>` + `Automatic merge failed; fix conflicts and then commit the result.` を出し `repo.merging = {"from": name, "conflicts": [...]}` | 無い枝: `merge: <name> - not something we can merge` / 自分自身: `Already up to date.`（正常終了）/ `merging` 中: `Error: you have unmerged files; resolve them and commit first` |
| `git status` | 従来の 2 行の前に、repo があれば `On branch <name>` と `merging` 中なら `You have unmerged paths.` を出す | — |
| `git commit -m` | 従来 + repo があれば現在の枝の tree を更新・log に追加。`merging` 中なら log に `Merge branch '<name>'` を積み `merging` を消す。**競合マーカーが残っていても実 git と同じく成功する**（見抜くのは `case_file.sh` の判定） | 従来どおり |
| `gh pr create --title "<t>" --body "<b>"` | 現在の枝から PR を作る。`--body` 省略可。`#<n>` と URL（`https://hq.example/casework/pull/<n>`）を出す | main から: `Error: no commits between main and main` / 同じ枝で open な PR あり: `Error: a pull request for branch '<name>' already exists` |
| `gh pr view [n]` | タイトル・枝・state・レビュー。レビューは **Mission の `pr_review` ルール**（judge.py の `PR_REVIEWS[mission_id]`）で毎回評価し、指摘が残れば `CHANGES_REQUESTED`（各指摘を `- ` 行で）、無ければ `APPROVED`。n 省略時は現在の枝の PR | 無い番号: `Error: no pull request found for #n` |
| `gh pr list` | open な PR の一覧 `#n  <title>  <branch>` | — |
| `gh pr merge [n]` | `APPROVED` のときだけ枝を `main` に取り込み（競合なし前提。あれば `Error: cannot merge, resolve conflicts on the branch first`）、PR を `merged` に。cwd 配下の中身も main に切り替わる | 未承認: `Error: pull request #n is not approved` |

- `gh` は Level 4〜5 帯の新コマンドとして allowlist に追加（`git` と同じく PATH 解決の対象外の組み込み扱い）
- レビュールール（Mission25）: report.txt に `/root/team_desk/cctv.log` の絶対パス引用がある / `suspects.txt` に載っている
  名前が含まれる。どちらかが欠けると Changes requested、両方揃えば Approved（`case_file.sh` の判定と同じロジックを共有）
- 判定（judge.py 専用ロジック）:
  - Mission23: `checkout -b` で切った枝で commit がある + `main` の tree に港の追記（`HARBOR`）がある + merge 実行の証跡
  - Mission24: `statement.txt` に競合マーカーが無い + 正しい時刻 `23:50` が残る + `Merge branch 'reed/statement'` の log がある。
    マーカー残り: `Error: unresolved conflict markers in statement.txt` / 誤った側: `Warning: the statement contradicts cctv.log`
  - Mission25: PR が `merged` + その PR に `CHANGES_REQUESTED` → 追加 commit → `APPROVED` の履歴がある（一発承認は不可: 初回の
    report は必ず指摘が付く構造にする＝初期 report テンプレに絶対パス引用が無い）

### 5c. サーバー編の基盤（追加エピソード Mission26〜28。2026-09-13 確定、実装中）

予約済みホスト `archive_node`（オンプレ）と `corp_server`（クラウド）を `SSH_HOSTS` に追加し、ホスト定義に
**サーバーの身体情報**を持たせる。値は静的、`systemctl start/stop` による変化だけ state（`state["remote_services"][host][name]`）
に記録する（`rm` 禁止と同じ思想で `disable`/`mask`/削除系は作らない）。

ホスト定義の追加キー（`SSH_HOSTS[host]`）:

```python
"hostname": "archive-node-01",
"uname": "Linux archive-node-01 6.1.0-18-amd64 #1 SMP Debian 6.1.76-1 x86_64 GNU/Linux",
"services": {  # systemctl / journalctl / ss の元
    "archive-indexer": {"state": "failed", "description": "Archive indexer", "port": None,
                        "journal": ["Mar 03 02:14:07 archive-indexer[812]: write /var/lib/index/db: No space left on device", ...]},
    "sshd": {"state": "active", "description": "OpenSSH server", "port": 22, "journal": [...]},
},
"disk": [  # df -h の行（Filesystem Size Used Avail Use% Mounted on）
    {"fs": "/dev/sda1", "size": "40G", "used": "12G", "avail": "26G", "pct": 32, "mount": "/"},
    {"fs": "/dev/sdb1", "size": "20G", "used": "19.6G", "avail": "400M", "pct": 98, "mount": "/var"},
],
"sizes": {"/var/log/spool.log": "17G", "/var/log/syslog": "220M", ...},  # du -sh の元（無いパスは content 長から算出）
"ip": [{"iface": "eth0", "addr": "192.168.10.5/24"}],
"metadata": None,  # クラウドのみ: {"instance-id": "i-0f3e9a7c2b1d4e5f6", "region": "ap-northeast-1", "local-ipv4": "10.0.3.17"}
"cron_jobs": [...],  # remote 中の crontab -l の元（local は従来どおり state["cron_jobs"]）
```

| コマンド | 挙動（remote 中はそのホストの値。local は事務所の既定値） |
|---|---|
| `hostname` | ホスト名（local は `office`） |
| `uname -a` / `uname` | `uname` 文字列（`-a` 無しはカーネル名 `Linux` のみ） |
| `cat /etc/os-release` | remote FS に静的ファイルとして置く（`PRETTY_NAME="Debian GNU/Linux 12 (bookworm)"` 等） |
| `df -h` | ヘッダ + `disk` の各行。`df` 単体は KB 単位に換算しない（`-h` 前提。無しでも同じ表を返す） |
| `du -sh <path>` | `sizes[abs_path]` があればそれ、無ければ配下 content 長の合計を人間可読に。`du -sh /var/log/*` は glob 展開後に各行 |
| `systemctl status <svc>` | `● <svc> - <description>` / `   Active: active (running) since …` または `failed (Result: exit-code)` / 直近 journal 3 行。未知: `Unit <svc>.service could not be found.` |
| `systemctl start/stop/restart <svc>` | `remote_services` に状態を記録。出力なし。`stop` した `sshd` は `ss -tln` から 22 が消える。local（事務所）では `Error: command not allowed`（サーバーでだけ触れる） |
| `journalctl -u <svc> [-n N]` | `-- Logs begin at … --` + journal 行（末尾 N 行。既定は全部） |
| `ip a` / `ip addr` | `ip` の各 iface（`inet <addr>`）。local は `lo` + `eth0 10.0.0.2/24` |
| `ss -tln` | `services` のうち state=active かつ port を持つものを LISTEN 行に。local は 22 のみ（従来どおり） |
| `curl <url>` | mock API 限定。`http://169.254.169.254/latest/meta-data/<key>` は remote 中の `metadata[key]` を返す（無ければ `404 - Not Found`）。`…/meta-data/` はキー一覧。それ以外の URL は `curl: (6) Could not resolve host: <host>` |

判定（judge.py 専用ロジック。command_log は remote 中のコマンドも生テキストで残る）:
- Mission26: `df` + `du` + `systemctl status archive-indexer` + `journalctl -u archive-indexer` の 4 手 + report に `/var/log/spool.log` と
  `No space left` の両方。欠け: `Warning: diagnose before you report（df/du/systemctl/journalctl）`
